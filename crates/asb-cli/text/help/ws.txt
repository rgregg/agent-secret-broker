usage: asb ws NAME URL [--ttl 15m|900] [--max-frames N]     open (a human approves one card); prints the session id
       asb ws send [ID] TEXT|-                                one text frame (- reads stdin)
       asb ws recv [ID] [--wait S] [--max N] [--json]         frames from the server, one per line
       asb ws close [ID]
       asb ws [ID] [--linger S] [--close]                     line pipe: stdin lines are sent, frames printed

URL is ws:// or wss:// on a host and port the credential allows. The broker connects, signs in with the
credential's handshake (set by the operator; you never see the token) and relays text frames. ID defaults
to $ASB_WS_SESSION. Nothing you send is filtered once the session is approved; the credential is masked in
what you receive, binary frames are not shown. The pipe waits --linger seconds (default 2) after the last
line or frame before it exits, and leaves the session open unless --close is given.
Exit 0 ok, 2 usage, 3 broker error or refused (not set up, host not allowed, too many sessions), 4 denied,
5 open unanswered, 7 ended (expired, closed, revoked, idle, server closed, unknown), 8 refused (cap, rate, size).
example: asb ws ha wss://ha.example.com:8123/api/websocket --ttl 10m
         asb ws send ID '{"id":1,"type":"get_states"}' && asb ws recv ID --wait 5
