usage: asb request-credential NAME --kind token|login --for "purpose"
                              [--host H[,H]]... [--var VAR] [--mode http|env]
       asb request-credential NAME --replace --for "purpose" [--var VAR]

Ask the human to supply a credential the broker does not have yet. You never see the value:
they type it on the approval page, which stores it in the vault. --kind token is one API
token or key; login is a username and password. --for says what it is for (one line, up to
300 characters; the human sees it as your unverified claim). --host (repeatable, or comma
separated) suggests the hosts it may be used against; the human confirms or edits them.
--var suggests the placeholder name (for a login, the prefix of NAME_USERNAME and
NAME_PASSWORD). --mode http (default) needs hosts; env may be used without hosts.
Waits for the human (about 15 minutes), then prints "stored: NAME". Exit 0 stored, 4 denied,
5 expired, 3 refused (the name exists: use --replace), 2 usage. Never reads stdin; never
put a secret in an argument.
--replace asks for a NEW VALUE of a credential that already exists (a token that expired or was
rotated). The human types it on the approval page; the old value is kept as previous_value. Only
the value changes: the hosts and approval policy stay. --var says which variable when the
credential has several (a login's password, say). It takes no --kind, --host or --mode. Prints
"replaced: NAME". Exit codes as above; 3 also when NAME does not exist or is an SSH key.
example: asb request-credential myapi --kind token --for "read the Example API" --host api.example.com
         asb request-credential myapi --replace --for "the token expired; I need a new one"
